# 역동감 규칙 (동작 JSON 을 쓸 때 지킬 것)

`anims/common/*.json` 을 새로 쓰거나 고칠 때 이 규칙을 지킨다. 2D 핵앤슬래시 기준이다.
`docs/motion_design.md` 는 "동작마다 어떤 몸놀림인가", 이 문서는 "어느 동작이든 역동적으로 보이려면 숫자가 얼마여야 하는가"이다.
둘이 어긋나면 이 문서의 숫자를 따르고, 설계 문서의 표도 맞춰 고친다.

- 칸은 **키 48칸 기준 칸**이다 (`angles` 출력, `root` 의 `x`/`y`/`fwd` 와 같은 단위). 128칸 설정에서도 그대로 쓴다.
- 시간은 `frame_ms` 의 ms 다. 단계 시간 = 그 단계 프레임들의 `frame_ms` 합.
- 숫자는 첫 기준값이다. 사람이 편집기로 재생해 보고 바꾼 값이 있으면 그 값을 따른다.
- 규칙을 어길 이유가 있으면 어겨도 된다. 다만 결과 보고에 "R5 를 어김: 이유" 처럼 적는다.

---

## 1. 규칙

### R1. 시간 강약 — 빠른 곳과 느린 곳의 차이를 크게

- 반복하지 않는 동작(공격·스킬·회피)은 **가장 긴 프레임 ≥ 가장 짧은 프레임 × 3**.
- 휘두름(무기가 크게 지나가는 프레임)은 **1~2프레임, 각 30~50ms**.
- 준비 끝 멈춤(정점)은 **80~150ms**, 뻗음 멈춤은 **100~180ms**. 무거운 무기·스킬은 위쪽 값.
- 반복 동작(대기·걷기·달리기·대쉬)은 `frame_ms` 를 고르게 둬도 된다. 대신 R6·R8 의 자세 차이로 강약을 낸다.

### R2. 시간 예산 — 조작이 굼뜨지 않게

시작 = 0번 프레임부터 첫 휘두름 프레임 **전까지**의 합. 회복 = 뻗음·넘침이 끝난 뒤부터 마지막까지의 합.

| 종류 | 시작 | 휘두름 | 뻗음+넘침 | 회복 | 전체 |
| --- | --- | --- | --- | --- | --- |
| 가벼운 공격 (1타·2타) | 150~250 | 40~80 | 150~250 | 150~250 | 500~750 |
| 이어 베기 (콤보 2타 이후) | 100~200 | 40~80 | 150~250 | 150~250 | 450~700 |
| 무거운 공격·스킬 | 300~450 | 40~100 | 200~350 | 200~300 | 850~1200 |
| 회피 (구르기·대쉬 출발) | 30~70 | — | — | 80~150 | 400~600 |

- 시작이 예산을 넘으면 **준비 앞쪽 프레임(무게 싣기)** 부터 줄인다. 정점 멈춤과 휘두름은 줄이지 않는다.
- 회복이 길면 끈적해진다. 줄일 때는 회복 프레임 수를 줄이지 말고 프레임마다 시간을 줄인다 (자세는 부드럽게, 시간은 짧게).

### R3. 준비 동작 — 반대로 먼저 간다

- 본동작이 가는 방향과 **반대로** 먼저 움직인다. 준비 끝 값과 본동작 끝 값은 **부호가 반대**여야 한다.
  - 가로 베기: `torso` `twist` 를 반대쪽으로 20~35도 감았다가, 휘두름에서 반대 부호로 풀어 준비 끝과 **합쳐 40~70도** 바뀌게.
  - 내려베기: `torso` `swing` 을 뒤로 8~15도 젖혔다가(음수) 앞으로 10~18도 숙인다.
  - 점프·도약: 무릎을 굽혀 몸이 2~4칸 내려앉은 뒤 뛴다.
- 준비 끝 자세는 정점 멈춤(R1)으로 잠깐 보여 준다.

### R4. 몸 전체로 친다 — 팔만 움직이지 않는다

공격의 휘두름~뻗음 구간에서 아래를 **모두** 만족한다.

| 부위 | 값 |
| --- | --- |
| 몸 전체 앞으로 | `root` `fwd` 를 시작 대비 **+2~4칸** (가벼운 공격), **+4~8칸** (돌진·스킬). 회복에서 0 으로 되돌리지 않아도 된다 (게임에서 이동으로 처리할 때는 되돌린다) |
| 앞발 내딛기 | 앞다리 `thigh` `swing` +25~35, `shin` 으로 무릎 굽힘. 뒷다리는 뒤로 펴짐 (`thigh` -15~-25) |
| 몸통 | R3 의 비틀기·숙이기 변화량 |
| 머리 | 몸통과 같은 쪽으로, 몸통 변화의 30~50% |
| 반대팔 | 무기 팔과 반대로 흔든다 (균형). 무기 팔 `swing` 변화의 20~40% |

### R5. 시간차 — 부위마다 늦게 도착한다

- 정점·뻗음에서 **모든 뼈가 같은 프레임에 멈추지 않는다.** 힘이 몸 가운데에서 끝으로 전해지는 순서로 늦게 도착시킨다:
  `root`·다리 → `torso` → `upper_arm` → `forearm` → `hand`·무기 → 망토(`follow`)
- 한 단계 늦을 때마다 **0~1프레임**. 몸통이 정점에 닿은 뒤 1~2프레임 지나 칼끝이 정점에 닿게 한다.
- 열쇠 시각은 프레임 시각에만 둔다. 반복이 아니면 `i / (frames - 1)`, 반복(`loop`)이면 `i / frames` 다. 사이 시각에 두지 않는다.

### R6. 멈춤 열쇠(`"ease"`)는 적게

- `"ease"` 는 **동작의 시작·끝**, 그리고 **무기 쪽 정점·뻗음**에만 붙인다.
- 한 동작에서 `"ease"` 열쇠는 전체 열쇠의 **25% 이하**. 넘으면 열쇠마다 멈칫거려 로봇처럼 보인다.
- 몸통·다리는 정점에서 멈추지 말고 다음 자세로 계속 흐르게 둔다 (R5 와 함께).
- 떨어지는 구간·휘두름 구간 열쇠에는 `"ease"` 를 붙이지 않는다 (빨라져야 할 곳에서 느려진다).

### R7. 넘침과 되돌아옴 — 멈출 때 조금 더 간다

- 뻗음 다음 1~2프레임에서 무기·팔이 **같은 방향으로 5~10도 더** 갔다가 돌아온다.
- 64칸에서 보여야 한다: `angles` 로 잰 칼끝 위치가 뻗음 프레임 대비 **2칸 이상** 움직여야 한다. 1칸 이하면 넘침이 없는 것과 같다.
- 망토는 `follow` 로 맡긴다. 공격·스킬은 `gain` 1.1~1.3, 대기·걷기는 1.0.

### R8. 끝 자세는 크게 — 64칸에서 보일 만큼

- 뻗음 프레임에서 칼끝은 몸 가운데(`frame` 가운데 세로줄)에서 가로로 **16칸 이상** 떨어진다.
- 정점과 뻗음은 실루엣(검은 그림자로 칠했을 때 모양)이 **대기 자세와 확 달라야** 한다. 두 그림자를 겹쳤을 때 거의 겹치면 다시 쓴다.
- 들어 올리는 중간 프레임과 뻗음 프레임의 칼끝은 서로 **10칸 이상** 떨어진다 (같은 자리면 같은 자세로 보인다).
- 위아래 움직임 크기:

| 동작 | 몸 높이 변화 |
| --- | --- |
| 대기 숨쉬기 | 1칸 |
| 걷기 | 1~2칸 |
| 달리기 | 2~3칸 (날기 프레임 가장 높음) |
| 공격 내딛기 | 1~2칸 내려앉음 |
| 착지·내려찍기 충격 | 3~5칸 내려앉음 |

- 칼끝·손끝·발끝이 이웃 열쇠와 **1칸 미만**으로만 다른 열쇠는 64칸에서 안 보인다. 빼거나 키운다 (대기는 예외).

### R9. 동작선 — 몸이 한 줄기 곡선을 이룬다

- 정점·뻗음·착지 자세에서 몸이 똑바로 서 있으면 안 된다. `torso` `swing` 과 `head` `swing` 을 **같은 부호**로, 합쳐 **15~30도** 기울인다.
- 앞으로 치는 자세는 뒷발 → 엉덩이 → 머리 → 칼끝이 한 방향으로 기운 사선(앞으로 쏠린 C 모양)이 되게 한다.
- 준비 끝 자세는 그 반대쪽으로 휜 곡선이 되게 한다 (R3).

### R10. 무게 — 공중과 착지

- 뛰어오름은 빠르게 시작해서 점점 느려지고(정점 근처 프레임 시간을 길게), 떨어짐은 점점 빨라진다(떨어지는 프레임 시간을 짧게, `"ease"` 없음).
- 착지 프레임: 무릎을 크게 굽히고(`thigh` `swing` +30~50, `shin` -40~-70), **120~200ms** 머문다. `ground` 가 몸을 내려 준다.
- 공중 구간만 `ground` 0, 열쇠에 `"ease"` 를 붙여 땅 붙이기가 넘치지 않게 한다 (기존 규칙 그대로).

### R11. 타격 프레임 알리기 — 멈춤 효과는 게임에서

- 때리는 프레임(휘두름의 마지막 프레임)을 `"events": {"hit": [번호]}` 에 넣는다. 공격·스킬은 **반드시** 넣는다.
- 다음 타로 넘어갈 수 있는 첫 프레임을 `"cancel": [번호]` 로 넣는다 (보통 넘침이 끝난 프레임).
- `events` 는 Unity 내보내기(`--unity`)의 `manifest.json` 으로 그대로 넘어간다.
- 맞았을 때 화면을 잠깐 멈추는 효과(가벼운 공격 50~80ms, 무거운 공격 100~150ms)는 **그림에 넣지 않는다.** 맞았을 때만 멈춰야 하므로 게임 코드가 `hit` 를 받아 처리한다.

### R12. 이어지는 동작

- 1타의 끝 자세(뻗음) = 2타의 시작 자세. 2타는 대기 자세에서 시작하지 않는다.

### R13. 반복 동작의 강약

| 동작 | 지킬 것 |
| --- | --- |
| 대기 | 숨 1칸. 망토·머리가 몸통보다 반 박자 늦게 |
| 걷기 | 몸통 앞뒤 2~4도 흔들림, 팔 ±15~25도, 내려앉기 프레임이 가장 낮음 |
| 달리기 | 몸통 앞으로 10~15도, 팔 ±35~50도(무기 팔은 반), 날기 프레임에서 두 발 모두 공중 |
| 대쉬 | 몸통 앞으로 20~30도, 무기·망토는 뒤로 끌림, 망토 `gain` 1.2 이상 |

## 2. 작업 순서

1. **표부터 쓴다.** 프레임마다 `번호 | 단계 | 시간 | 몸놀림` 표를 쓰고, R2 의 시작·회복·전체 시간을 계산해 적는다. 예산을 넘으면 표에서 고친다.
2. **끝 자세 셋을 먼저 정한다.** 준비 끝·뻗음·착지(있으면). R3·R4·R8·R9 를 이 자세에서 맞춘다. 사이 자세는 그다음.
3. **시간차를 넣는다.** 부위마다 정점 열쇠를 R5 순서대로 0~1프레임씩 민다.
4. **JSON 을 쓴다.** `"interp": "spline"`, `frame_ms`, `events`, `follow`, `trail` 을 모두 넣는다.
5. **숫자 검사**(아래 3장)를 하고, `render` → `angles` → 프레임 그림 확인 (`sprite-animate` 5단계).
6. 사용자에게 편집기로 **재생해 보고** 다듬어 달라고 한다. 정지 그림만으로 역동감을 판단하지 않는다.

## 3. 자기 검사표

결과 보고에 이 표를 채워 넣는다. 하나라도 "아니오"면 고치거나 이유를 적는다.

| 번호 | 검사 | 재는 법 |
| --- | --- | --- |
| R1 | 가장 긴 프레임 ≥ 가장 짧은 × 3 (반복 동작 빼고) | `frame_ms` |
| R2 | 시작·회복·전체가 예산 안 | `frame_ms` 합 |
| R3 | 준비 끝과 본동작 끝의 몸통 값 부호가 반대 | `torso` 열쇠 |
| R4 | 휘두름에서 `root` `fwd` +2칸 이상, 앞발 내딛기 있음 | `root`·`thigh` 열쇠 |
| R5 | 몸통 정점이 칼끝 정점보다 1~2프레임 앞 | 열쇠 시각 |
| R6 | `"ease"` 열쇠 25% 이하 | 열쇠 개수 |
| R7 | 넘침 프레임에서 칼끝 2칸 이상 이동 | `angles` 칼끝 위치 |
| R8 | 뻗음 칼끝이 가운데에서 16칸 이상 | `angles` 칼끝 위치 |
| R9 | 끝 자세에서 몸통+머리 15도 이상 같은 쪽 기울기 | `torso`·`head` 열쇠 |
| R11 | `events` 에 `hit`·`cancel` 있음 | JSON |

## 4. 하지 말 것

- 모든 프레임을 같은 시간으로 두기 (반복 동작 빼고)
- 모든 뼈를 같은 시각에 `"ease"` 로 멈추기
- 팔만 돌리고 몸통·다리·`root` 는 그대로 두기
- 정점·뻗음에서 차렷처럼 곧게 선 자세
- 1칸도 안 움직이는 넘침, 1칸도 안 움직이는 사이 열쇠
- 멈춤 효과(히트스톱)를 `frame_ms` 로 그림에 박아 넣기
- 정지 그림 한 장만 보고 "역동적이다"라고 판단하기
