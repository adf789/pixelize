  • 두 시드 모두 Kaggle 이 가장 밝다. 머리도 원래 그림처럼 갈색이다. 이 PC 결과는 머리가 더 까맣다.
  • q8 은 f16 보다 더 어둡다. 시드 42 는 몸 전체가, 시드 1380986812 는 머리만 어둡다.
  • 그래서 80칸 정면 스프라이트에서 q8 은 얼굴 살색이 거의 보이지 않는다. Kaggle 이 얼굴이 가장 잘 보인다.
  • 망토 뒷면: 시드 42 의 이 PC f16 에는 붉은 글자 같은 무늬가 생겼고 q8 에는 없다 (둘 다 회색빛). 시드 1380986812 는 이 PC f16·q8 이 붉고 Kaggle 이 회색빛이다.
  • 신발: 시드 42 의 Kaggle 은 옆모습에서 신발 끝이 살짝 말려 올라갔다.
  • 눈으로 본 평가: 시드 1380986812 의 이 PC f16 이 가장 나쁘다 (턱이 뾰족하고 색이 그림과 안 어울린다). 전체로는 Kaggle 이 가장 낫다.

이 PC q86~7분모양은 f16 과 거의 같고 색은 더 어둡다시드 여러 개를 빨리 훑어볼 때
  • 품질은 가중치(f16·q8)보다 시드에 따라 더 크게 달라진다. 시드 몇 개를 돌려 미리보기를 보고 고르는 게 낫다.
  • 두 시드만 비교했다. "이 PC 가 늘 더 어둡다", "q8 이 늘 더 어둡다"고 단정하기는 이르다.
  • Kaggle 조건: 인터넷, 전화 인증을 마친 계정, 주간 무료 GPU 시간(30시간쯤)에서 빠짐, 붐비면 차례를 기다림, 그림이 Kaggle 비공개 데이터셋에 올라감.

5남은 일

  • pixel-pipeline/trellis.py 의 기본은 아직 이 PC f16 이다. Kaggle 을 기본으로 할지, q8 을 고를 수 있게 할지 정한다.
  • 시드 여러 개를 한 번에 돌려 미리보기를 한 장으로 모아 고르는 기능이 있으면 좋다. Kaggle 은 실행 파일·가중치를 한 번만 받고 여러 시드를 돌리면 시간이 덜 든다.
  • GTX 16xx 는 텐서 코어가 없어 ggml 이 CMAKE_CUDA_ARCHITECTURES=61-virtual;80-virtual 과 GGML_CUDA_FORCE_MMQ 로 직접 빌드하라고 권한다. 배포판 CUDA 12 판은 60;61;70 으로 빌드되어 이 카드에서는 sm_70 코드가 돌 것이라 시험하지 않았다.

# 이 PC f16 (trellis.py 기본)
.venv\Scripts\python.exe trellis.py 정면그림.png --out work\test\warrior.glb --seed 42

# Kaggle f16
.venv\Scripts\python.exe trellis.py 정면그림.png --out work\test\warrior.glb --seed 42 --backend kaggle

# q8 가중치 받기 (tools\trellis_cpp\models\q8\ 에 들어간다)
.venv\Scripts\hf.exe download ilintar/trellis2-gguf q8/birefnet.gguf q8/dinov3.gguf q8/ss_flow.gguf q8/ss_dec.gguf q8/shape_flow_512.gguf q8/shape_dec.gguf q8/tex_flow_512.gguf q8/tex_dec.gguf --local-dir tools\trellis_cpp\models

# 이 PC q8 (trellis.py 에 옵션이 아직 없어 직접 돌린다)
tools\trellis_cpp\bin\trellis-cli.exe 정면그림.png out.glb --models tools\trellis_cpp\models\q8 --res 512 --seed 42 --atlas 1024 --webp off --dump-bg --require-gpu
비교 렌더와 숫자(윤곽 겹침, 밝기)는 임시 스크립트로 만들었고 저장소에는 넣지 않았다. 그림을 누르면 원래 크기로 열린다.
