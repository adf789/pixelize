# sprite-animate

`D:\private_workspace\pixelize` 의 `animate.py` 를 돌려 캐릭터 동작 스프라이트를 만든다.
모든 명령은 이 폴더에서 `animate.bat` (내장 Python) 으로 실행한다. 자세한 설명은 `README.md`.

## 0. 준비 확인

- 캐릭터 폴더: `characters/<이름>/front.png`, `back.png`, `left.png` (있는 것만 처리)
  - 앞·뒤는 팔을 벌린 T자 자세, 옆은 팔을 내려도 된다. 옆 그림은 왼쪽을 보게 하고 `left.png` 로 둔다.
  - 오른쪽 그림(`right.png`)은 왼쪽 rig·조각을 다 고친 뒤 `animate.bat mirror characters/<이름> left right` → `animate.bat parts characters/<이름> --views right` 로 만든다.
  - 대각선(8방향): `front_left.png`, `back_left.png` 를 넣고 `rig --views front_left back_left` → 확인·추가 뼈 → `parts --views ...` → `mirror front_left front_right`, `mirror back_left back_right` → `parts --views front_right back_right`. 그림 규격은 `docs/extra_art_guide.md`.
  - **새 방향을 더할 때 `rig` 는 꼭 `--views` 를 준다.** 안 주면 이미 고친 다른 방향 rig 를 덮어쓴다.
  - 등을 덮은 망토처럼 거리로 가를 수 없는 부분은 추가 뼈에 `claim`(색상·상자)을 준다 (README "8방향").
  - 단색 배경. 아래 "Front" 같은 글자는 자동으로 지워진다.
- 사용자가 다른 이름으로 그림을 줬으면 이 이름으로 **복사**한다 (원본은 건드리지 않는다).

## 1. 관절 찾기

```
animate.bat rig characters/<이름>
```

`characters/<이름>/rig_<방향>.json` 과 `check/rig_<방향>.png` 가 생긴다.
**이미 고친 rig 파일이 있으면 덮어쓰므로, 처음 한 번만 돌린다.**

## 2. 관절 확인하고 고치기 (반드시 그림을 본다)

`check/rig_<방향>.png` 를 Read 로 열어 본다. 흰 점이 관절, 굵은 선이 뼈, 작은 색 점이 "이 자리는 어느 뼈를 따라가는가"이다. 100칸 눈금으로 좌표를 읽는다.

고칠 것:
- 관절이 실제 위치에서 벗어남 → rig JSON 의 `joints` 좌표를 고친다 (원본 그림 픽셀 좌표).
  - 옆 그림은 `_l`(보이는 팔다리)과 `_r`(뒤쪽 복사본)을 **같은 좌표**로 둔다.
- 망토·머리카락·꼬리·치마처럼 팔다리에 붙어 있지만 따로 움직여야 할 부분이 팔다리 색으로 칠해짐
  → `extra_bones` 에 뼈를 추가한다. 그 부분 가운데를 지나도록 시작·끝점을 잡는다.
  ```json
  "extra_bones": [
    {"name": "cape", "parent": "torso", "start": [220, 220], "end": [275, 610], "depth": 0.5}
  ]
  ```
- 칼·방패·지팡이처럼 **휘지 않는 물건**을 손에 쥐게 하려면 → `attachments` 에 그림 한 장을 뼈에 붙인다.
  ```json
  "attachments": [
    {"name": "sword", "image": "sword.png", "grip": [45, 430], "tip": [45, 6],
     "bone": "hand_r", "length": 22, "angle": 0, "depth": 4.5}
  ]
  ```
  - `image`: 캐릭터 폴더 안의 투명 배경 PNG. `grip`(손잡이), `tip`(끝)은 **그 그림 안의** 픽셀 좌표 — 그림을 Read 로 열어 정한다.
  - `bone` 위 `at`(기본 0.5) 자리에 손잡이가 오고, 뼈 방향에서 `angle`도(시계 방향 양수) 돌린 쪽으로 끝이 향한다.
  - `length`: 손잡이→끝 길이를 최종 픽셀(64칸 기준)로. `depth`: 앞뒤 순서 (뒤 그림에서는 몸 뒤라 작게).
  - 붙인 물건은 `name` 으로 동작에서 뼈처럼 돌릴 수 있다 (손목 꺾기). 확인 그림에는 흰 네모로 보인다.
  - 모든 방향에서 같은 손(`hand_r`)에 붙인다. 왼쪽 그림에서는 뒤쪽 손이라 `depth` 를 몸 뒤(0.5)로 둔다 (`mirror` 가 오른쪽 그림에서는 몸 앞으로 바꿔 준다).
  - 보는 사람 쪽으로 기운 모습의 그림(45도, 정면)이 있으면 `variants` 로 넣는다 (README "칼 각도별 그림").
- 갑옷·투구·옷처럼 **몸에 딱 붙어 같이 휘는 장비**는 → `layers` 에 덮개 그림을 넣는다.
  ```json
  "layers": [
    {"name": "helmet_iron", "slot": "helmet", "image": "helmet_iron_front.png"},
    {"name": "helmet_gold", "slot": "helmet", "image": "helmet_gold_front.png"}
  ]
  ```
  - 덮개 그림은 **그 방향 원본 그림과 같은 크기**의 투명 PNG 이고, 원본 위에 겹쳤을 때 딱 맞는 자리에 그려져 있어야 한다 (AI 인페인팅으로 원본의 그 부분만 다시 그린 뒤 그 부분만 남기면 된다).
  - 같은 `slot` 의 층은 서로 바꿔 끼우는 변형이다. 합친 시트에는 slot 마다 **첫 번째** 층만 들어간다.
  - `"in_sheet": false` 를 주면 그 층은 합친 시트에서 빠지고 층 시트(`--layers`)에만 나온다. 모든 방향의 그림이 없는 장비에 쓴다.
  - 덮개는 몸과 같은 그물·무게로 휜다. 메시는 몸과 모든 덮개를 합친 모양에 씌운다.
  - 붙인 물건(`attachments`)도 `slot` 을 줄 수 있다. 같은 slot 의 물건들은 뼈 하나(이름 = slot)를 함께 쓴다.
- 겹칠 때 앞뒤가 틀림 → `depth` (큰 수가 앞). 추가 뼈는 각자 `depth` 를 갖는다.
- 팔을 내린 기본 자세가 어색함 → `base_pose` 의 `rot` (모든 동작에 더해진다).

고친 뒤:
```
animate.bat check characters/<이름>
```
확인 그림을 다시 보고, 맞을 때까지 반복한다.

## 2-1. 조각 나누기 (조각 방식 — 큰 동작은 반드시 이 방식으로)

```
animate.bat parts characters/<이름>          # 이미 있으면 건너뜀. 다시 만들려면 --force
```

`check/parts_<방향>.png` 를 Read 로 연다. 조각마다 다른 부위가 섞이지 않았는지, 분홍(채운 곳)이 가려진 자리에만 있는지 본다.
출력의 "다시 쌓기 차이"는 0% 여야 한다. 조각이 잘못 나뉘면 rig 의 관절·추가 뼈를 고치고 `--force` 로 다시 만든다.
손으로 고친 조각이 있으면 `--force` 를 쓰지 않는다.
- 조각이 있으면 `render` 는 저절로 조각 방식으로 그린다 (출력 첫 줄에 `조각 방식` / `그물 방식` 이 나온다). 예전 방식은 `--mesh`.
- 망토 같은 추가 뼈 조각에 장식(주머니, 끈)이 섞여서, 망토를 움직이면 그 장식이 몸에서 떨어져 떠 보이면 → 그 장식 자리에 추가 뼈를 하나 더 준다 (`parent` 는 `torso`). 그다음 `parts --force`.

## 3. 동작 쓰기

**먼저 `docs/motion_design.md` 의 몸놀림 설계를 읽고 따른다.** 단계(준비·휘두름·뻗음·회복 등)와 프레임별 시간이 정해져 있다.
**`docs/motion_rules.md` 의 역동감 규칙(R1~R13)도 지키고, 결과 보고에 그 문서의 자기 검사표를 채워 넣는다.** 두 문서가 어긋나면 규칙 문서의 숫자를 따른다.
- 새 동작은 `"interp": "spline"` 과 `"frame_ms": [...]` 를 쓴다. 멈춰야 하는 열쇠(정점, 뻗음)만 `[시각, 값, "ease"]`.
- 자연스러움은 정지 그림으로 판단하기 어렵다. 초안을 만든 뒤 사용자에게 **편집기(`editor.bat`)로 재생해 보고 다듬어 달라고** 한다.
  사용자가 저장하면 그 파일로 `render` 해서 검사·시트를 만든다.

**새 동작은 네 방향 공통으로 `anims/common/<동작>.json` 에 한 번만 쓴다.** 앞·뒤·왼쪽·오른쪽이 모두 같은 몸놀림을 따른다 (README "네 방향 공통 동작").
```json
{
  "frames": 16, "loop": false, "interp": "spline", "frame_ms": [...],
  "keys": {
    "root":        {"swing": [[0, 0], [0.5, 15]]},
    "upper_arm_r": {"swing": [[0, 0], [0.4, 160], [0.7, 20]], "spread": [[0, 0], [0.4, 20]]}
  },
  "views": {"front": {"trail": [9]}, "left": {"trail": [9]}}
}
```
- `swing` = 앞뒤로 휘두르기 (팔다리 끝이 앞으로 +, 몸통·머리·root 는 앞으로 숙이기 +), `spread` = 옆으로 벌리기 (팔다리 바깥쪽 +), `twist` = 제 축으로 비틀기, `len`. `root` 는 `x`(캐릭터 왼쪽)/`y`(아래)/`fwd`(앞) 이동도.
- 방향마다 다른 값(궤적 프레임, `view_swap`, 그 방향만 더할 2D `keys`, 그 방향에서만 바꿔 쓸 공통 채널 `common`)은 `views.<방향>` 에 넣는다.
- 칼을 뻗는 자세는 앞 그림과 옆 그림에서 모두 보이게 "앞·옆·아래 사이 대각선"으로 둔다 (예: 오른팔 swing 64, spread -37). 한쪽으로만 뻗으면 다른 그림에서는 보는 사람 쪽을 향해 짧아져 사라진다.
- 땅에 서 있는 동작은 `"root": {"ground": [[0, 1]]}` 로 바닥 붙이기를 켠다. 무릎을 굽히면 몸이 저절로 내려앉으니 `y` 로 맞추지 않는다. 공중 구간만 0 (열쇠에 `"ease"` 를 붙여 넘치지 않게).
- 망토는 `"follow": {"cape": {"of": "torso", "lag": 2}, "cape_l": ..., "cape_r": ...}` 로 늦게 따라오게 한다 (방향마다 망토 뼈 이름이 다르다).
- 돌리는 순서는 twist → spread → swing: 팔을 앞으로 든 채(swing 90) spread 를 바꾸면 가로 베기. 머리 위 내려베기는 swing 을 160 → 50 으로, 몸 앞을 가로지르면 spread 를 음수로.
- 앞 그림에서 보는 사람 쪽을 향한 칼은 짧아져 몸에 묻힌다. 칼이 보여야 하는 프레임(뻗음)은 몸 옆으로 비스듬히 둔다.
- 지금 초안 8개를 만든 값 표는 `anims/common/*.json` 그대로다. 고칠 때는 편집기로 열어 재생하며 고친다.
- 확인은 네 방향 모두 한다 (`--only front/<동작> back/<동작> left/<동작> right/<동작>`).

예전 방향별 동작 `anims/<방향>/<동작>.json` 도 그대로 쓸 수 있다 (같은 이름의 공통 동작이 있으면 공통 동작이 이긴다). 아래는 방향별 형식이다.
이미 있는 idle / walk / run / attack / attack2 / skill / roll / dash 를 본보기로 삼는다.
앞 그림 한 장으로는 앞으로 공중제비 도는 모습(머리 꼭대기·등이 보이는 프레임)을 만들 수 없다. 앞·뒤 구르기는 몸을 공처럼 웅크리는 것으로 표현한다.

```json
{
  "frames": 8, "fps": 10, "loop": true,
  "keys": {
    "root":    {"y":   [[0, 0], [0.25, -1], [0.5, 0], [0.75, -1], [1, 0]]},
    "thigh_l": {"rot": [[0, 25], [0.5, -25], [1, 25]]}
  }
}
```

- 열쇠 프레임은 `[시간 0~1, 값]`. 사이는 부드럽게 이어진다. 반복 동작은 `1` 의 값을 `0` 과 같게 둔다.
- 보는 사람 쪽(z축) 움직임: `tilt` (앞뒤로 기울이기, 뼈 방향으로 짧아짐 — 앞 그림에서 상체 숙이기), `turn` (제 축으로 돌리기, 폭이 좁아짐 — 몸통 비틀기), `z` (앞뒤 순서, 자식도 함께 — 팔을 몸 뒤로). tilt·turn 은 그 뼈 모양만 줄이고 자식은 자리만 따라온다.
- 채널: `rot` (도, **화면에서 시계 방향이 양수**), `len` (뼈 방향 늘이기 비율, 1=그대로), `x`/`y` (**키 48칸 캐릭터의 1칸**. 칸(`frame`)을 키워도 그대로이고, `char_height` 를 바꾸면 함께 늘고 준다 — 붙인 물건의 `length` 도 같다).
- 값은 `base_pose` 위에 더해진다 (`len` 은 곱해진다).
- 뼈: `root`(몸 전체. `x`/`y` 로 옮기고 `rot` 으로 몸통 가운데를 중심으로 돌린다 — 구르기는 옆에서 `rot` 0 → -360), `torso`, `head`, `upper_arm_l/r`, `forearm_l/r`, `hand_l/r`, `thigh_l/r`, `shin_l/r`, `foot_l/r`, 그리고 rig 의 추가 뼈와 붙인 물건(`sword` 등). 그 방향 rig 에 없는 뼈는 무시된다.
- 동작 시트는 `config.json` 의 `frame`(96칸) 크기라 캐릭터 둘레에 여백이 있다. 그래도 잘리면 동작을 억지로 줄이기보다 `frame` 을 키우는 것을 먼저 생각한다.
- **회전값은 지나가는 길까지 정한다.** 열쇠 사이는 숫자가 이어지는 쪽으로 돈다. 165 → -35 는 숫자가 줄어드는 쪽(앞 그림이면 몸 바깥, 옆 그림이면 등 뒤 아래)을 돌아가고, 165 → 325 는 반대쪽(머리 위)을 넘어간다. 끝 자세가 같아도 길이 다르다.
  - 머리 위를 넘어 내려치는 베기는 같은 방향으로 계속 이어 적는다 (옆: -165 → -230 → -310, 앞: -195 → -35).
  - 칼을 들어 올릴 때 몸 바깥으로 크게 돌리지 말고 몸 앞을 가로질러 끌어올리면 도는 각도가 작다.
- 프레임 시각(8프레임이면 0, 0.143, 0.286 …)마다 열쇠를 두어야 그 프레임 자세가 정확히 정해진다.
- 들어 올리기처럼 한 프레임에 칼이 100도 넘게 도는 곳은 프레임을 늘려 나눈다. 베는 순간은 궤적으로 표현한다:
  `"trail": [5]` (5번 프레임에 칼날이 지나온 길을 반달로 칠함). `true` 면 크게 돈 프레임 모두.
- 그 방향 그림에 없는 면이 보여야 하는 구간(앞으로 구를 때의 등)은 다른 방향 그림으로 그린다:
  ```json
  "view_swap": [{"from": 0.4, "to": 0.62, "view": "back", "mirror": true,
                 "add": {"root": {"rot": 180, "y": 9}, "sword": {"rot": 150}}}]
  ```
  `from`~`to` 시각의 프레임을 `view` 그림으로, `mirror` 면 좌우를 뒤집은 값으로, `add` 를 더해서 그린다.
- 다리를 `len` 으로 줄이면 발이 골반 쪽으로 올라가 떠 보인다. 그만큼 `root` `y` 로 몸을 내린다. 시트에서 프레임마다 맨 아래 픽셀 줄을 재서 0번 프레임과 맞춘다.
- 방향 감각:
  - 앞: 캐릭터 오른쪽(`_r`)이 화면 왼쪽. `upper_arm_r` 양수 = 바깥(화면 왼쪽)으로 들어 올림. 앞 그림에서 다리를 드는 건 `len` 을 줄여서 표현한다.
  - 왼쪽(left, 왼쪽을 봄): 팔다리 양수 = 앞으로, 몸통 음수 = 앞으로 숙임, 망토 음수 = 뒤로 날림. 오른쪽(right)은 부호가 반대.
  - 뒤: 보통 앞 동작을 좌우로 뒤집어 쓴다 → `{"mirror_of": "front/walk"}`
- 64칸에서는 1칸보다 작은 움직임이 안 보인다. 몸 위아래 흔들림은 1~2칸으로 준다.

## 4. 만들기

기본은 픽셀 조각 방식(조각을 한 번 픽셀로 만들어 RotSprite 로 돌림 — 깜빡임이 적다). 예전 방식과 비교하려면 `--filter`.


```
animate.bat render characters/<이름> -o output/<이름>
animate.bat render characters/<이름> -o output/<이름> --only left/attack front/walk   # 일부만 빠르게
animate.bat render characters/<이름> -o output/<이름> --layers   # 장비 바꿔 끼우기용 층 시트도 만든다
```

`--layers` 를 주면 `output/<이름>/layers/<방향>_<동작>/<순위>_<층>.png` 와 `layers.json` 이 생긴다.
층마다, 그리고 앞뒤 순서(depth)마다 시트를 나눈다. 그래서 게임에서 `sorting_order` 순서대로 쌓기만 하면 팔이 갑옷 앞으로 오는 장면도 맞게 겹친다.

## 5. 결과 확인 (반드시 그림을 본다)

**프레임 하나하나를 크게 본다.** 여러 프레임을 한 줄로 작게 붙인 그림만 보고 "괜찮다"고 하지 않는다.
**경고 0개는 "잘리거나 끊기지 않았다"는 뜻일 뿐, 동작이 그 동작처럼 보인다는 뜻이 아니다.**

0. 동작을 쓰기 전에 단계를 정한다. 공격이면 준비 → 들어 올리기 → **베기(무기를 몸에서 멀리 쭉 뻗음)** → 휘두른 뒤(잠깐 멈춤) → 돌아오기.
   - 베는 프레임에서 무기가 몸에 붙어 아래로 늘어지면 차렷 자세처럼 보인다. 앞 그림에서 "앞으로 내려치기"는 몸에 겹쳐 안 보이므로 옆(오른쪽 아래 등)으로 뻗는다.
   - 들어 올리는 중간 프레임이 베는 프레임과 비슷하면 안 된다 (같은 쪽으로 같은 높이에 뻗지 않는다).
   - **회전값을 머릿속으로 더해 자세를 짐작하지 않는다.** 서 있을 때도 아래팔·무기는 위팔보다 20도쯤 바깥으로 기울어 있어서 "회전 0 = 똑바로 아래"가 아니다. 원하는 화면 각도를 정하고, 아래로 실제 각도를 재서 맞춘다:
     ```
     animate.bat angles characters/<이름> front/attack left/skill
     ```
     프레임마다 위팔·아래팔·무기의 화면 각도(0=오른쪽, 90=아래, 180=왼쪽, -90=위)와 무기 끝 위치가 나온다.
   - 다 만든 뒤 **프레임마다 "의도한 단계 / 실제로 보이는 자세"를 표로 적어** 비교한다. 다르면 고친다.

1. 출력의 `주의 …` 와 `output/<이름>/check/warnings.json` 을 본다. 경고 종류:
   | 경고 | 뜻 | 고치는 곳 |
   | --- | --- | --- |
   | 칸 밖으로 잘림 | 64칸 가장자리에 닿음 | 움직임을 줄이거나 무기를 눕힌다 |
   | 관절 벌어짐 / 관절 틈 | 조각 사이가 떨어져 보임 | 그 뼈의 `x`/`y` 이동을 없애거나, 회전을 줄인다 |
   | 순간이동 | 손끝·발끝·머리가 한 프레임에 25칸 넘게 감 | 사이 열쇠 프레임을 넣거나 프레임 수를 늘린다 |
   | 한 프레임에 N도 회전 | 무기가 크게 건너뜀 | 중간 프레임을 넣거나, 게임에서 칼 궤적 효과를 붙인다 |
2. `output/<이름>/check/<방향>_<동작>_frames.png` 를 Read 로 연다 — 프레임마다 5배, 경고 난 프레임은 빨간 테두리.
   경고가 없어도 모양(뭉개짐, 부위가 떨어져 떠 보임, 이상한 꺾임)을 프레임마다 본다.
3. `output/<이름>/check/<방향>_<동작>.png` 위 줄은 줄이기 전 큰 그림이다. 관절 이음새처럼 64칸에서 안 보이는 것은 여기서 본다.
`--layers` 로 만들었으면 맨 아래 줄에 층 시트를 순서대로 쌓은 결과가 있다 — 가운데 줄과 외곽선만 빼고 같아야 한다.

| 보이는 문제 | 고치는 곳 |
| --- | --- |
| 다른 부분(망토, 천)이 팔다리를 따라 끌려감 | rig `extra_bones` 추가 → 2단계 |
| 관절이 엉뚱한 곳에서 꺾임 | rig `joints` → 2단계 |
| 팔다리가 몸 뒤로 숨거나 앞으로 튀어나옴 | rig `depth` |
| 무기가 엉뚱한 쪽을 가리킴 | rig `attachments` 의 `angle`, 또는 동작의 무기 `rot` / `forearm` 부호 |
| 동작이 너무 작아 안 보임 / 과함 | anims 값 |
| 그림이 찢어지거나 크게 늘어남 | 회전을 줄이거나, 사이 열쇠 프레임을 넣는다 |

고친 뒤 `--only` 로 그 동작만 다시 만들어 확인한다. 만족스러우면 전체를 한 번 더 돌린다.
