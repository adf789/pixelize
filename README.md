# pixelize

AI로 뽑은 캐릭터 일러스트를 **64×64 픽셀 그림**으로 바꾸는 도구.
모든 그림에 같은 규칙(키, 발 위치, 색 수, 외곽선)을 적용해서 결과를 일정하게 맞춘다.

## 설치

`python\`(Python 3.12 내장판)과 `models\`(자세 인식 모델)는 용량이 커서 저장소에 넣지 않는다.
새로 받았을 때:

1. Python 3.12 내장판(Windows embeddable)을 `python\` 에 풀고, `python312._pth` 의 `import site` 줄 앞 `#` 을 지운다.
2. `get-pip.py` 로 pip 를 깐 뒤:
   ```
   python\python.exe -m pip install -r requirements.txt
   ```
3. 모델은 `animate.bat rig` 를 처음 돌릴 때 `models\` 에 저절로 받아진다 (약 220MB).

## 사용

```
pixelize.bat input\hero -o output\hero -c config.json
```

- `input/hero/` 에 `hero_front.png`, `hero_side.png`, `hero_back.png` 처럼 **한 캐릭터의 그림을 한 폴더에** 넣는다.
- 한 폴더의 그림은 **팔레트(색 묶음)를 함께 쓴다.** 그래서 앞/옆/뒤 색이 서로 어긋나지 않는다.
- 결과:
  - `output/hero/hero_front.png` … 실제로 Unity에 넣을 64×64 그림
  - `output/hero/preview/` … 눈으로 보기 쉽게 8배로 키운 그림
  - `output/hero/palette.hex` … 이번에 만든 팔레트

## 처리 순서

1. 배경 지우기 — 네 모서리 색을 배경으로 보고, 테두리와 이어진 비슷한 색을 투명하게 만든다. 이미 투명 배경이면 건너뛴다.
2. 작은 조각 지우기 — 본체와 떨어진 작은 덩어리(그림 아래 "Front" 글자, 티끌)를 지운다.
3. 팔레트 정하기 — 원본 그림들의 색에서 팔레트를 만든다 (또는 정해 둔 팔레트를 쓴다).
4. 크기 맞추기 — 원본 색을 팔레트 색으로 바꾼 뒤, 캐릭터 키가 `char_height` 칸이 되도록 칸마다 **가장 많이 나온 색 하나**를 고른다. 평균을 내지 않으므로 색이 섞여 탁해지지 않는다. 발끝은 바닥에서 `foot_margin` 칸 위에 맞춰 가운데 둔다.
5. 외곽선 — 바깥쪽에 1칸 테두리를 두른다.

## 설정 (`config.json`)

| 항목 | 기본값 | 뜻 |
| --- | --- | --- |
| `canvas` | 64 | 그림 한 장의 가로·세로 칸 수 |
| `char_height` | 48 | 캐릭터 키(칸). 무기 휘두르기와 효과가 들어갈 자리를 남기려고 64보다 작게 잡음 |
| `foot_margin` | 4 | 바닥에서 발끝까지 띄울 칸 수. 모든 캐릭터의 발이 같은 줄에 선다 |
| `colors` | 24 | 팔레트를 새로 만들 때 쓸 색 수 |
| `palette` | null | 정해 둔 팔레트 파일(`.hex`) 경로. 설정 파일 위치 기준. 비우면 그림에서 새로 만든다 |
| `alpha_threshold` | 128 | 이 값보다 진하면 "보임"으로 친다 (0~255) |
| `bg_tolerance` | 40 | 배경색과 얼마나 달라도 배경으로 볼지 (0~255) |
| `min_part_ratio` | 0.02 | 가장 큰 덩어리의 이 비율보다 작은 떨어진 조각은 지운다. 떨어진 무기 등이 지워지면 낮춘다 |
| `outline` | true | 외곽선을 두를지 |
| `outline_color` | `#1b1325` | 외곽선 색 |
| `preview_scale` | 8 | 미리 보기 확대 배율 |

### 게임 전체 색을 맞추는 방법

1. 첫 캐릭터를 돌리면 `palette.hex` 가 나온다. (또는 Lospec 같은 곳의 `.hex` 팔레트를 받아도 된다.)
2. 이 파일을 `palettes/game.hex` 로 옮기고 `config.json` 의 `"palette": "palettes/game.hex"` 로 지정한다.
3. 그 뒤로 만드는 캐릭터·몬스터는 모두 같은 색만 쓴다.

## AI 그림을 뽑을 때 지킬 것

64칸으로 줄이면 아주 작아지므로, **단순한 그림일수록 결과가 좋다.**

- 단색 배경 (흰색이나 연한 회색), 그림자 없음
- 전신, 발끝까지 잘리지 않게
- 굵은 외곽선, 평평한 색, 큰 덩어리 (잔무늬·질감 빼기)
- 머리를 크게 (2~3등신) — 작은 그림에서 얼굴이 보이려면 필요하다
- 앞/옆/뒤를 **한 장에 나란히** 뽑은 뒤 잘라 쓰면 서로 모양이 덜 어긋난다
- 게임에 넣을 그림은 팔 벌린 자세(T자) 대신 **팔을 내린 자연스러운 서기 자세**로 뽑는다. T자 자세는 Spine 같은 뼈대 작업용이다
- 어두운 옷만 입히면 작아졌을 때 덩어리로 뭉친다. 밝은 색 부분(천, 장식)을 크게 넣으면 잘 읽힌다

지시문 예시:

```
character turnaround sheet, front view, side view, back view, same character,
top-down RPG game character, chibi proportions, full body, standing pose,
thick dark outline, flat colors, simple shapes, no texture, no shadow,
plain white background, <캐릭터 설명>
```

## 알아 둘 점

- 자동 결과는 **바탕 그림**이다. 눈·손·무기 같은 작은 부분은 Aseprite에서 몇 칸 손보는 게 좋다.
- 왼쪽 그림은 따로 만들지 않고 옆 그림을 Unity에서 `SpriteRenderer.flipX` 로 뒤집어 쓴다.
- Unity 그림 설정: `Filter Mode = Point`, `Compression = None`, `Pixels Per Unit = 64`, 기준점(Pivot)은 발끝 위치인 `Custom (0.5, 0.0625)` (= `foot_margin` 4 ÷ 64).

# animate — 뼈대 동작 → 픽셀 스프라이트

T자 일러스트에 뼈대를 심어 걷기·뛰기·공격 같은 동작을 만들고, 프레임마다 위의 픽셀화 규칙(키, 발 위치, 팔레트, 외곽선)으로 찍는다.
Claude 에게는 **`/sprite-animate` 스킬**(`.claude/skills/sprite-animate/SKILL.md`)로 맡기면 된다.

## 흐름

```
animate.bat rig    characters\warrior                     # 1. 관절 찾기 → rig_<방향>.json, check\rig_<방향>.png
(확인 그림을 보고 rig_<방향>.json 고치기)
animate.bat check  characters\warrior                     # 2. 고친 rig 로 확인 그림만 다시
animate.bat render characters\warrior -o output\warrior   # 3. 동작 만들기
animate.bat render characters\warrior -o output\warrior --only left/attack   # 일부만
animate.bat mirror characters\warrior left right         # 왼쪽 그림을 뒤집어 오른쪽 그림·rig 만들기
animate.bat rig    characters\warrior --views front_left    # 새로 넣은 방향만 관절 찾기 (고친 rig 를 덮어쓰지 않게)
animate.bat parts  characters\warrior --views right      # 그 방향 조각만 만들기
```

## 조각 방식 (만드는 중)

그림 한 장을 휘는 지금 방식은 크게 웅크리거나 숙이는 자세에서 그림이 늘어나고 뭉개진다.
그래서 부위별 조각을 딱딱하게 돌리는 방식(컷아웃)으로 옮기는 중이다.

1. **조각 나누기** (완료): `animate.bat parts characters\warrior`
   - `characters\<이름>\parts\<방향>\<부위>.png` — 원본과 같은 크기의 투명 PNG. 그림 도구에서 층으로 열어 고칠 수 있다. 이미 있으면 `--force` 없이는 덮어쓰지 않는다.
   - 부위: 뼈마다 하나 + **골반(`hips`)** + 추가 뼈(망토). 골반을 따로 두어 몸통을 숙여도 허리띠·앞치마가 끌려가지 않는다.
   - 오리는 규칙: 뼈대 무게로 나눈 뒤, 팔다리는 뼈에서 굵기의 1.5배 안쪽만 갖는다. 팔다리 굵기는 앞(T자) 그림에서 재서 다른 방향에도 쓴다. 옆 그림의 앞쪽 팔은 몸통 위에 겹쳐 있으므로 팔 굵기 안쪽을 팔로 가져온다. 떨어진 부스러기는 이웃 조각에 붙인다.
   - **가려진 곳 자동 채우기**: 앞쪽 조각에 가려진 곳을 OpenCV `inpaint` 로 주변 색을 번지게 채운다. 몸통·골반은 볼록 껍질 안쪽까지 채운다.
   - **관절 덮개**: 뼈 시작 관절 둘레(그 조각 굵기만큼)의 이웃 픽셀을 붙여, 돌려도 틈이 덜 보이게 한다.
   - 확인: `check\parts_<방향>.png` (분홍 = 채운 곳, 하늘색 = 관절 덮개). 조각을 다시 쌓아 원본과 다른 픽셀 비율을 출력한다 (0% 여야 한다).
2. **조각 돌리기** (완료): `render` 는 `parts\<방향>\parts.json` 이 있으면 조각 방식으로 그린다 (`--mesh` 를 주면 예전 그물 방식).
   - 조각마다 자기 뼈의 행렬로 딱딱하게 돌리고 옮겨(`cv2.warpAffine`) 앞뒤 순서대로 쌓는다. 늘어나거나 눌리지 않는다.
   - 옆 그림 뒤쪽 팔다리는 보이는 쪽 조각을 어둡게 복사해 쓴다. 칼(`attachments`)은 그대로 붙는다.
   - 장비 층(`layers`)은 원본에서 맨 위에 보이는 몸 조각을 따라 나눠, 그 조각과 같은 뼈에 붙인다.
   - 관절 이음새: 1단계의 관절 덮개만으로 무릎·팔꿈치·어깨를 크게 굽혀도 틈이 보이지 않아, 관절을 부드럽게 섞는 처리는 넣지 않았다.
   - 망토처럼 따로 움직이는 조각에 다른 장식(주머니 등)이 섞이면, 그 장식에 추가 뼈를 하나 더 준다 (옆 그림의 `pouch`).
3. **자동 검사와 큰 확인 그림** (완료): `render` 가 프레임마다 아래를 검사해 `주의 …` 로 출력하고 `check\warnings.json` 에 모은다.
   - 칸 밖 잘림.
   - 관절 벌어짐: 부모·자식 뼈가 들고 간 관절 위치가 1.5칸(64칸 기준)보다 벌어짐. 허벅지는 골반을 부모로 본다.
   - 관절 틈: 관절 둘레 원이 60%보다 덜 칠해지고 기본 자세보다 30%p 넘게 줄어듦. 원이 절반 넘게 칸 밖이면 뺀다.
   - 순간이동: 손끝·발끝·머리가 한 프레임 사이에 25칸보다 멀리 감.
   - 무기 회전: 무기가 한 프레임 사이에 100도보다 많이 돎 (뼈 사슬의 회전값을 더해서 잰다. 위치로는 180도가 넘는 회전의 방향을 알 수 없다).
   - 기준값은 지금 동작들의 실제 값을 재서 정했다. 일부러 팔꿈치를 떼고 몸을 칸 밖으로 보낸 시험 동작으로 경고가 잡히는 것도 확인했다.
   - 큰 확인 그림 `check\<방향>_<동작>_frames.png`: 프레임을 5배로 키우고, 경고가 난 프레임은 빨간 테두리와 경고 내용을 적는다.
4. **큰 동작 다듬기** (완료)
   - **동작 칸 키우기**: `config.json` 의 `frame`(96) / `frame_foot_margin`(12) 이 있으면 동작 시트의 칸만 96×96 으로 커진다. 캐릭터 키(48)는 그대로라 위 36칸·옆 24칸·아래 12칸이 비어, 칼을 들거나 뻗어도 잘리지 않는다. 정지 그림용 `pixelize.py` 는 `canvas`(64)를 그대로 쓴다.
   - **길이 단위**: 동작의 `x`/`y`, 붙인 물건의 `length` 는 "키 48칸 캐릭터의 1칸"이다. 칸을 키워도 그대로이고, 캐릭터 키를 바꾸면 함께 늘고 준다.
   - **다른 방향 그림 바꿔 끼우기(`view_swap`)**: 동작 안의 한 구간을 다른 방향 그림으로 그린다. 앞 구르기 가운데는 뒤 그림을 180도 돌려 "거꾸로 뒤집힌 등"을 보여 준다. 뒤 구르기는 `mirror_of` 로 앞 구르기를 뒤집어 쓰면 바꿔 끼울 그림도 앞 그림으로 바뀐다.
   - **칼 궤적(`trail`)**: 베는 프레임에 칼날이 지나온 길의 마지막 100도를 반달 모양으로 몸 뒤에 칠한다 (합친 시트에만, 층 시트에는 없다 — 게임에서 효과로 따로 붙이는 것을 권한다).
   - 결과: 24개 동작 경고 0개.
   - **각도 확인(`animate.bat angles 캐릭터폴더 front/attack ...`)**: 프레임마다 팔·무기의 실제 화면 각도와 무기 끝 위치를 출력한다. 회전값을 더해 자세를 짐작하면 틀리기 쉬워서(서 있을 때도 아래팔이 20도쯤 기울어 있다) 만들었다.
   - 저장할 파일이 그림 뷰어에 열려 있어 막히면, 잠깐 기다려 다시 시도하고 끝내 막히면 `_new` 를 붙여 저장한 뒤 계속한다.

## 동작 편집기

브라우저에서 동작을 **재생하며** 뼈를 마우스로 조절하고, 동작 JSON 형식 그대로 저장한다. 몸놀림 설계는 `docs\motion_design.md`.

```
editor.bat                     # → 브라우저에서 http://127.0.0.1:8765
editor.bat characters\다른캐릭터  # 다른 캐릭터 (조각이 있어야 한다)
```

| 조작 | 하는 일 |
| --- | --- |
| 뼈 클릭 | 그 뼈를 고른다 (오른쪽 판의 뼈 목록에서도 고를 수 있다. `root` = 몸 전체) |
| 끌기 | 고른 뼈를 관절 중심으로 돌린다 → 지금 프레임에 열쇠가 생긴다 |
| `Shift` + 끌기 | 몸 전체를 옮긴다 |
| `Alt` + 위아래 끌기 | 고른 뼈를 앞뒤로 기울인다 (`tilt`, 위로 끌면 보는 쪽으로) |
| `←` `→` / `Space` | 프레임 이동 / 재생 (프레임별 시간대로) |
| `K` / `Delete` | 고른 뼈의 열쇠 넣기 / 지우기 |
| 시간표 숫자 칸 | 그 프레임에 머무는 시간(ms) |
| 픽셀로 만들기 | 저장 후 `animate.py render` 로 시트를 만들어 프레임별 큰 그림과 경고를 보여 준다 |

- 앞뒤 프레임 겹쳐 보기, 64칸 대략 미리 보기(팔레트·외곽선 없음)를 켤 수 있다.
- `mirror_of` 로 뒤집어 쓰는 동작(뒤 그림)은 읽기 전용으로 열린다. "따로 편집하기"로 뒤집은 값을 분리할 수 있다.
- 편집기의 자세 계산은 `animate.py` 와 같다. 같은 프레임을 두 쪽에서 그려 비교하면 칠해진 영역이 99.9~100% 겹친다.
- `Ctrl`+`Z` / `Ctrl`+`Y` (`Ctrl`+`Shift`+`Z`): 되돌리기 / 다시 하기. 끌기 한 번이 한 번으로 묶인다.
- **켜 둔 채로 갱신**: 화면이 2초마다 서버에 물어본다.
  - 그림·rig·조각·설정(`config.json`)이 바뀌면 장면을 저절로 다시 읽는다.
  - 지금 연 동작 파일이 밖에서 바뀌면(예: Claude 가 고침) 다시 불러온다. 저장 안 한 변경이 있으면 알리기만 하고 덮어쓰지 않는다.
  - Python 코드(`animate.py` 등)가 바뀌면 위에 "편집기를 다시 켜야 반영됩니다"를 띄운다. 그때는 `editor.bat` 창을 닫고 다시 실행한다.
- 동작 목록의 "네 방향 공통" 동작을 열면 아래 공통 동작 방식으로 편집한다 (오른쪽에 네 방향 미리 보기, 누르면 그 방향으로).

## 네 방향 공통 동작

`anims\common\<동작>.json` 에 한 번 쓰면 앞·뒤·왼쪽·오른쪽 그림 모두 그 동작으로 만든다. 앞에서 팔을 앞으로 들면 옆 그림에서도 같은 만큼 들린다.
같은 이름의 방향별 파일(`anims\front\attack.json` 등)이 있어도 공통 동작을 쓴다.

- 뼈마다 몸 기준 각도(도)를 적는다. 몸 좌표는 X = 캐릭터 왼쪽, Y = 아래, Z = 캐릭터 앞.
  | 채널 | 뜻 | 그대로 보이는 그림 |
  | --- | --- | --- |
  | `swing` | 앞뒤로 휘두르기. 팔다리 끝이 앞으로 +, 몸통·머리·`root` 는 앞으로 숙이기 + | 옆 |
  | `spread` | 옆으로 벌리기. 팔다리는 바깥쪽 + (왼쪽·오른쪽 거울), 가운데 뼈는 앞 그림에서 시계 방향 + | 앞·뒤 |
  | `twist` | 제 축으로 비틀기. 팔다리는 바깥쪽 +, `root` 는 캐릭터 왼쪽으로 돌기 + | — |
  | `len` | 뼈 길이 비율 (2D 와 같음) | |
  | `root` 의 `x` / `y` / `fwd` | 캐릭터 왼쪽 / 아래 / 앞으로 이동 (칸) | |
  | `root` 의 `ground` | 바닥 붙이기 (0~1). 1 이면 몸(칼·망토 빼고)의 가장 낮은 곳이 발 높이에 닿도록 몸을 올리고 내린다. 무릎을 굽히면 저절로 내려앉고, 구르면 바닥을 따라 구른다. 공중 구간은 0 | |
- 돌리는 순서는 twist → spread → swing. 그래서 팔을 앞으로 든 채(`swing` 90) `spread` 를 바꾸면 수평으로 쓸고 지나간다 (가로 베기).
- **따라 움직임(`follow`)**: `"follow": {"cape": {"of": "torso", "lag": 2, "gain": 1}}` — 망토가 몸통·몸 전체가 돈 만큼을 2프레임 늦게 따라 돈다. 그 방향 rig 에 없는 뼈(앞 그림의 `cape_l`/`cape_r`, 옆 그림의 `cape`)는 건너뛴다.
- 방향마다 그 그림에 비춰 보이는 모양으로 바꾼다 (`common_anim.py`). 뼈 조각을 화면에 평평한 카드로 보고 3D 로 돌린 뒤 비춘 모양을 2D 의 `rot`·`tilt`·`turn` 으로 나누고, 보는 사람 쪽으로 나온 만큼 앞뒤 순서(`z`)를 정한다.
- 방향마다 따로 줄 값은 `views` 에 넣는다: `"views": {"front": {"trail": [6], "view_swap": [...], "keys": {...}}}`. `keys` 는 바꾼 자세 위에 더하는 2D 값(그 방향만 손볼 때). `common` 은 공통 채널을 그 방향에서만 통째로 바꿔 쓴다 — 앞·뒤 구르기는 몸 전체를 앞으로 돌리면 납작한 그림이 뒤집히기만 해서, `"common": {"root": {"swing": [...]}}` 로 조금만 숙이고 가운데는 반대쪽 그림으로 그린다. 편집기에서 그 방향을 보며 고치면 그 채널은 그 방향 값에 들어간다.
- 공통 동작의 무기 회전 경고는 화면에 보이는 칼날 방향으로 잰다. 칼이 보는 사람 쪽을 향해 반보다 짧아 보이는 프레임은 재지 않는다.
- 초안 8개(`idle` `walk` `run` `attack` `attack2` `skill` `roll` `dash`)가 `anims\common\` 에 있다 (`docs\motion_design.md` 설계대로). 예전 방향별 파일(`animsront` 등)은 지웠다 (git 기록에 남아 있다). 방향별 동작 형식은 지금도 쓸 수 있다.
- 오른쪽 그림이 없으면 `animate.bat mirror 캐릭터 left right` 로 왼쪽 그림을 뒤집어 만든다. 칼은 어느 방향에서도 오른손(`hand_r`)에 있고, 왼쪽 그림에서는 몸 뒤, 오른쪽 그림에서는 몸 앞에 그린다.

## 8방향 (대각선 그림)

방향은 `front` `back` `left` `right` 와 대각선 `front_left` `back_left` `front_right` `back_right` 의 8개다.
대각선은 이웃한 두 방향의 가운데(45도)로 바꿔 그린다. 그림 뽑는 법은 `docs\extra_art_guide.md`.

- 왼쪽 대각선 두 장(`front_left.png`, `back_left.png`)만 넣고 `rig --views` → `parts --views` 로 만든 뒤, 오른쪽은 `mirror` 로 뒤집는다.
  옆 그림이 아닌 그림을 뒤집으면 왼쪽·오른쪽 팔다리가 바뀌므로 관절·추가 뼈 이름의 `_l`/`_r` 도 바꿔 준다.
- 대각선은 두 팔다리가 다 보이지만 한쪽이 가깝다 (왼쪽 대각선은 캐릭터의 왼쪽). 먼 쪽 팔은 몸통 뒤(1.5), 먼 쪽 다리는 가까운 다리 뒤(0.8)에 그린다.
- **색으로 가져오기(`claim`)**: 등을 덮은 망토처럼 몸통·다리와 겹쳐 그려진 부분은 거리로 가를 수 없다. 추가 뼈에
  `"claim": {"hue": [-15, 12], "box": [x0, y0, x1, y1]}` 를 주면 상자 안에서 그 색상(빨강 0도 기준 각도)인 픽셀을 그 뼈 조각으로 가져온다.
  `mirror` 가 상자도 좌우로 뒤집는다.

## 칼 각도별 그림 (`variants`)

칼이 보는 사람 쪽으로 기울면, 납작하게 누른 그림 대신 그 각도에서 본 그림으로 바꿔 끼운다.

```json
"attachments": [{"name": "sword", "image": "sword.png", "grip": [127, 140], "tip": [127, 950], "bone": "hand_r", "length": 22,
  "variants": [{"image": "sword_45.png", "grip": [318, 85], "tip": [20, 635], "length": 16.2, "from": 30},
               {"image": "sword_tip.png", "grip": [172, 125], "tip": [172, 295], "length": 3.2, "from": 62}]}]
```

- 칼이 보는 사람 쪽(z > 0)으로 `from` 도 넘게 기울면 그 그림을 쓴다 (기본 그림은 30도 아래, 45도 그림은 30~62도, 정면 그림은 62도부터).
  보는 사람 반대쪽으로 기울면 기본 그림을 눌러 쓴다.
- `length` 는 그 그림 속 손잡이→끝이 화면에 보이는 길이(키 48칸 기준). 그림마다 축척이 다르면 코등이 폭으로 맞춰 정한다.
- 바꿔 끼운 그림은 이미 짧아진 모습이라 더 누르지 않는다 (모양 줄임이 빠진 행렬로 그린다). 편집기도 똑같이 고른다.

### 동작 파일에 새로 생긴 값

| 값 | 뜻 |
| --- | --- |
| `"frame_ms": [100, 50, …]` | 프레임마다 머무는 시간(ms). 없으면 `fps` 로 고르게. `animations.json` 에도 내보낸다 |
| `"interp": "spline"` | 열쇠 사이를 멈추지 않고 이어지는 곡선으로. 없으면 예전 방식(열쇠마다 감속·가속) |
| `[시각, 값, "ease"]` | 곡선 방식에서 이 열쇠에서는 멈췄다 출발한다 |
| `tilt` 채널 (도) | 보는 사람 쪽(+)/반대쪽(-)으로 기울이기. 뼈 방향으로 cos 만큼 짧아져 보인다 (앞 그림에서 상체 숙이기) |
| `turn` 채널 (도) | 뼈를 제 축으로 돌리기. 뼈와 수직 방향으로 cos 만큼 좁아져 보인다 (몸통 비틀기) |
| `z` 채널 | 앞뒤 순서 이동. 조각을 쌓는 순서 = depth + z. 자식 뼈도 함께 (팔을 몸 뒤로 넘기기) |

- `tilt`·`turn` 은 그 뼈의 모양만 줄이고, 자식 뼈는 모양은 그대로 둔 채 붙는 자리만 따라온다 (상체를 숙이면 머리는 내려오지만 납작해지지 않는다). 머리도 숙이려면 머리에 따로 준다.
- `z` 는 조각 방식에서만 쓴다 (그물 방식은 무시). `--layers` 층 시트는 depth + z 값마다 나뉜다.

## 원리

- **관절 찾기**: 자세 인식 모델(RTMW, `models\` 에 약 220MB 내려받음)이 어깨·팔꿈치·손목·골반·무릎·발목·발끝·얼굴을 찾는다.
- **그림을 자르지 않는다**: 그림 위에 촘촘한 그물(메시)을 씌우고, 그물 점마다 "그물을 따라 걸어서 가장 가까운 뼈 두 개"를 따라가게 한다. 고무판처럼 휘므로 관절에 틈이 생기지 않는다.
- **T자 팔 내리기**: 팔이 45도 넘게 벌어져 있으면 `base_pose` 로 자동으로 내린다. 모든 동작은 이 자세 위에 더해진다.
- **옆 그림(왼쪽·오른쪽)**: 두 다리가 겹쳐 있어 따로 움직일 수 없으므로, 보이는 팔다리(왼쪽을 보면 `_l`, 오른쪽을 보면 `_r`)를 복사해 어둡게 칠한 뒤쪽 팔다리로 쓴다.
- **추가 뼈(`extra_bones`)**: 망토처럼 팔다리에 붙어 있지만 따로 움직일 부분에 뼈를 더한다. 없으면 팔을 들 때 망토가 같이 끌려 올라간다.
- **붙인 물건(`attachments`)**: 칼처럼 휘면 안 되는 그림 한 장을 손 뼈에 붙인다. 그물로 휘지 않고 네모 그대로 손을 따라 움직이며, 동작에서 `sword` 같은 이름으로 손목처럼 돌릴 수 있다. 그 그림의 색도 팔레트에 들어간다. 형식은 스킬 문서 참고.
- **잘림 경고**: 그림이 64칸 가장자리에 닿으면 `주의 … 칸 밖으로 잘림` 을 출력한다.
- **장비 층(`layers`)**: 갑옷·투구처럼 몸에 붙어 같이 휘는 장비는 원본과 같은 크기의 덮개 그림으로 넣는다. 몸과 같은 그물로 휘므로 프레임이 저절로 맞는다. 같은 `slot` 의 층은 바꿔 끼우는 변형이다. `"in_sheet": false` 인 층은 합친 시트에서 뺀다 (층 시트에는 나온다) — 지금 투구는 대각선 그림이 없어서 8방향이 같은 모습이 되도록 뺐다.
- **층 시트(`--layers`)**: 층마다, 그리고 앞뒤 순서(depth)마다 시트를 나눠 낸다. 몸 하나도 "다리 / 몸통 / 머리 / 팔"처럼 여러 장으로 나뉘는데, 그래야 팔이 갑옷 몸통 앞으로 오는 장면도 쌓는 순서만으로 맞게 겹친다.
  - 64칸의 한 칸이 여러 시트에 걸치면 구멍이 나지 않도록, 칠할지는 합친 모양으로 정하고 가장 많이 차지한 시트가 그 칸을 맡는다.
  - 층 시트에는 외곽선을 두르지 않는다 (겹친 경계에 검은 줄이 생기므로). 외곽선은 게임에서 다 쌓은 뒤 한 번 두른다.

### 장비 조합 수

투구 10 × 갑옷 10 × 무기 10 을 통째로 그리면 1,000벌이지만, 층으로 나누면 몸 1 + 10 + 10 + 10 = 31벌이다.
색만 다른 변형은 그림을 만들지 않고 게임에서 팔레트를 바꿔 끼운다.

## Unity 에 넣기

- 시트를 `Sprite Mode = Multiple`, `Grid By Cell Size 64×64` 로 자른다.
- 기준점은 `animations.json` 의 `pivot` (발끝).
- 왼쪽 방향은 옆 시트를 `SpriteRenderer.flipX` 로 뒤집어 쓴다 (옆 그림이 왼쪽을 보므로, 오른쪽으로 갈 때 뒤집는다).

### 장비 바꿔 끼우기 (`--layers`)

- `layers.json` 의 `parts` 하나마다 `SpriteRenderer` 를 하나 두고 `sortingOrder` 를 `sorting_order` 로 맞춘다. 같은 `slot` 의 변형들은 `sorting_order` 가 같으므로 한 렌더러를 같이 쓴다.
- 2D Animation 패키지의 `Sprite Library` / `Sprite Resolver` 로 묶으면, 동작은 "프레임 번호"로만 돌고 장비를 바꿀 때는 그 slot 의 그림 묶음만 갈아 끼우면 된다.
- 외곽선은 캐릭터 전체를 다 그린 뒤 외곽선 셰이더로 한 번 두른다.
